# OPTIMAL: Offshore Freshened Groundwater Prospecting using Machine Learning

Open-science code and data release for the **OPTIMAL** project (Offshore Freshened
Groundwater Prospecting using Machine Learning).

This repository contains the surrogate-modelling and numerical-modelling workflow, the
post-processing and data-engineering scripts, and the machine-learning training and test
datasets developed during the project. It is intended to make the methodology transparent
and reproducible, in line with the project's open-science and data-management commitments.

> **Note:** This `optimal-opentools` branch holds the curated, shareable versions of the
> scripts and data. Working and development versions are maintained separately on `main`.

---

## Project overview

Offshore freshened groundwater (OFG) refers to water stored in sediment pores and
fractured rock below the seafloor with a salinity lower than seawater. It has been
identified on continental margins worldwide and proposed as an unconventional resource
that could help alleviate water stress in coastal regions. A central challenge is the
scarcity of subsurface data to constrain where these systems occur and how large they are.

OPTIMAL addresses this data-scarcity problem by combining process-based hydrogeological
modelling with machine learning. The approach uses comparatively abundant topographic and
bathymetric data to predict OFG occurrence and characteristics. The project has two
objectives:

- **O1** – Develop a methodology that uses machine learning to predict the occurrence of
  an OFG system and its properties (offshore extent, depth, and fresh-to-brackish water
  ratio) from sea-level history and the geomorphological characteristics of the continental
  margin and hinterland.
- **O2** – Apply the model globally to infer the occurrence and distribution of OFG.

## Workflow

The workflow follows a four-stage pipeline. The `src/` subfolders are numbered to reflect
the execution order and map directly onto the project work packages (WPs).

1. **Surrogate model generation (WP1)** — Complex continental-margin geometries are
   converted into standardised two-dimensional continental-shelf transects. Statistical
   distributions of the key shelf parameters (inland elevation, coastal sediment thickness,
   unconsolidated groundwater system thickness, shelf width, shelf-break depth and
   slope-domain geometry) are derived from open-source global datasets sampled along many
   transects, per continental region. Surrogate model realisations are then generated by
   randomly sampling these distributions and building geologically representative cross
   sections with stochastic porosity and hydraulic-conductivity distributions, using
   [ArchPy](https://github.com/randlab/ArchPy). Feature engineering derives additional
   physically meaningful variables (for example shelf width-to-depth ratio, seafloor
   gradient, aquifer-to-overburden thickness ratio). 5,000 realisations are generated per
   region.

2. **Numerical modelling (WP2)** — Boundary conditions are assigned to each realisation to
   simulate freshened groundwater emplacement and survival over two glacial-interglacial
   cycles, using variable-density groundwater flow and salt transport. Domains are
   discretised at 100 m horizontally and 10 m vertically.

3. **Post-processing and data engineering (T3.1)** — Simulation outputs are read and the
   target variables for machine learning are extracted for each model domain: offshore
   extent of freshened groundwater, freshwater volume, and fresh-to-brackish water ratio.
   These targets are stored alongside the input parameters and engineered features to form
   the labelled training dataset.

4. **Machine learning (WP3)** — The labelled dataset is used to train and evaluate a binary
   classifier (predicting OFG presence or absence from shelf geometry) and a multi-output
   regression model (predicting resource-feasibility characteristics). This component is
   under active development; see [Status](#status).

## Data

- **`data/surrogate_parameters/`** — Parameter tables generated for each continental region,
  one row per surrogate model realisation.
- **`data/numerical_outputs/`** — Outputs of the numerical simulations. *(Large files: see
  Data availability below.)*
- **`data/ml_training_test/`** — The labelled dataset split into training and test sets,
  combining input parameters, engineered features and extracted target variables. This is
  the machine-learning-ready data.

Data are organised by continental region (North America, Caribbean, South America, northern
Eurasia, southern Eurasia, Africa, Greenland/Iceland, Australia and Antarctica). Small
islands, island chains and polar margins were excluded from the initial implementation, as
their shelf and groundwater systems require separate parameterisation.

### Data sources

The workflow draws on the following open-source global datasets:

| Dataset | Description | Reference |
|---------|-------------|-----------|
| GEBCO 2014 | Global topography and bathymetry | Weatherall et al. (2015) |
| ATE | Unconsolidated groundwater system thickness estimation | Zamrsky et al. (2018) |
| SoilGrids | Soil layer thickness | Hengl et al. (2014) |
| GLOBSED | Global ocean sediment thickness | Straume et al. (2025) |
| COSCAT | Segmentation of the shelf and basins | Meybeck et al. (2006) |
| MARCATS | Global continental shelf polygons used to identify the shelf break | Laruelle et al. (2013) |
| Seafloor sediment type | Seafloor lithology classification | Dutkiewicz et al. (2015) |
| Earth coastlines | Map and ecological inventory of global coastlines | Sayre et al. (2021) |
| GSHHS | Global Self-consistent Hierarchical High-resolution Shorelines | Wessel and Smith (1996) |

## Requirements and installation

The workflow is implemented in Python. Transect extraction additionally uses ArcGIS Pro.

```bash
# clone the open-tools branch
git clone --branch optimal-opentools <REPO_URL>
cd optimal-opentools

# create and activate an environment, then install dependencies
pip install -r requirements.txt
```

Core Python dependencies include NumPy, SciPy, Pandas, scikit-learn and ArchPy.
